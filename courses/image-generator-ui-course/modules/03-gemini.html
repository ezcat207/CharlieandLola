Commissioning the Artist

The whole "Charlie & Lola style" is one paragraph of English. Here is how it gets sent, and what the app does around it.

There is no "Charlie & Lola" button

Open the generator and look at the prompt box on the right. You can read the entire product in there — and you are allowed to edit it.

Nobody trained a Charlie-and-Lola machine. Someone wrote a paragraph describing exactly how the drawing should look, and the app sends that paragraph plus your photo to a general-purpose artist, every single time you press the button.

🖍️
The metaphor for this module: commissioning an illustrator

You are not applying a filter. You are handing a freelance illustrator a written brief and a reference photo, and waiting for what comes back. The "style" you picked in the interface is the brief.

The intelligence is rented. These five jobs are the app.

The drawing talent belongs to Google. Everything the app itself contributes fits on five cards — and every one of them is a place things break.

The brief you are allowed to rewrite

This is the actual prompt the app sends, sitting in the source as one very long line. Read it as what it is: instructions to a freelancer.

📜
From the brief itself

"…thin sketchy outlines, flat colors, childlike proportions, playful hand-drawn charm…"

"Retain the subject's original clothing, hairstyle, facial features, accessories, skin tone, pose, and expression…"

"Negative Prompt: No realistic shading, no detailed rendering, no anime or manga style, no 3D modeling, no photographic textures!"

Every good image brief has the same three-part shape. This structure transfers to any image model you will ever use.

🎯

What to make

The look you want, in concrete visual words: sketchy outlines, flat colours, childlike proportions.

🔒

What to preserve

The things from the photo that must survive: clothing, hairstyle, skin tone, pose, expression.

🚫

What to forbid

The negative prompt — the list of default habits the model must resist.

Notice what this means for you: if the output keeps losing people's glasses, the fix is a few words added to the "retain" list. No new logic, no new deploy of clever code — just better writing.

Sealing the parcel

The brief and the photo have to travel together, in one shape the artist recognises. Here is that parcel being built.

CODE 
    const imageEditPrompt = [
      { text: charlieLolaPrompt },
      {
        inlineData: {
          mimeType: mimeType,
          data: base64Image,
        },
      },
    ];
PLAIN ENGLISH

Make the parcel we are about to hand the illustrator. It is a list with exactly two things in it.

Thing one: the written brief — that long Charlie & Lola paragraph.

Thing two starts here: the reference photo.

inlineData = the photo rides inside the message, not as a link to fetch later.

Tell the artist what kind of file it is — the MIME type, e.g. image/png.

And here is the photo itself, re-typed as one gigantic string of letters and numbers (base64).

Close the photo item.

Close the list. Parcel sealed, ready to send.

The actual AI call is four lines

All that hype, all that money, all that capability — and from the app's side it is one polite request with a name on it.

CODE 
      response = await ai.models.generateContent({
        model: "gemini-2.5-flash-image-preview",
        contents: imageEditPrompt,
      });
PLAIN ENGLISH

Send the commission and wait for the reply. await means: stop here, do nothing else, until the artist answers.

Which artist? This exact one, by name. Swapping models is one word on this line.

And here is what we are sending: the parcel we just sealed.

End of the request. Everything after this is dealing with whatever comes back.

ai.models Comes from Google's SDK — the ready-made toolkit Google publishes so nobody has to hand-write the plumbing
-flash- Google's name for the fast, cheap tier of the model family — a deliberate cost choice
-preview Not final. Google can change or retire it, and this line stops working the day they do

Opening the envelope

Gemini does not reply with a picture. It replies with candidates: a bag of parts, some text, hopefully one image. The route rummages until it finds the picture.

CODE 
    for (const part of response.candidates[0].content.parts) {
      if (part.inlineData) {
        generatedImageData = part.inlineData.data;
        generatedImageMimeType = part.inlineData.mimeType;
        break;
      }
    }
PLAIN ENGLISH

Take the first answer Gemini sent, and go through its parts one at a time.

Is this part a file rather than words? (Text parts have no inlineData.)

Yes — so keep the picture data.

And keep the note saying what kind of image file it is.

break = stop looking. We found what we came for; ignore the rest.

Close the "if it is a file" check.

Close the loop. If we got all the way here without finding one, there is no image — and the app says so.

🧭
Worth remembering when you debug

If a user ever sees "No image data found in Gemini API response", this loop ran and found nothing. The call worked, the key worked — the artist just replied with words instead of a drawing, usually a polite refusal.

Six keys, taking turns

Google puts a daily ceiling on each account. So this app holds six keys and rotates through them — a pattern called round-robin, the same way a deck of chores rotates through a house of flatmates.

CODE 
    // Try each key starting from current index
    for (let i = 0; i < this.apiKeys.length; i++) {
      const index = (this.currentIndex + i) % this.apiKeys.length;
      const keyStatus = this.apiKeys[index];

      if (keyStatus.isAvailable && keyStatus.requestCount < keyStatus.dailyLimit) {
        this.currentIndex = (index + 1) % this.apiKeys.length;
        keyStatus.lastUsed = new Date();
        keyStatus.requestCount++;
        return keyStatus.key;
      }
    }
PLAIN ENGLISH

A note left by whoever wrote this, for whoever reads it next.

Walk around the circle of keys once — at most six tries, then give up.

Start from wherever we stopped last time. The % (modulo) is a clock face — run past the last key and you wrap around to the first.

Pick up that key and its record card: is it healthy, how much has it spent today.

 

Two conditions, both required: this key is not marked burnt out, AND it is still under its daily allowance.

Good one. Move the pointer to the NEXT key straight away, so the following visitor gets a different one.

Stamp the time it was last used.

Add one to its tally for today.

Hand the key over. Done — nobody looks at the remaining keys.

Close the check.

Close the circle. If we get past here, all six were unusable.

💡
Aha: a rate limit is a nightclub capacity, not a fine

A rate limit does not charge you more when you go over. It stops letting you in. That is why apps pool keys: six doors instead of one, same club.

⚠️
The pool lives in memory, not in a database

The counters are in-memory, held by a single copy of the pool object (a singleton). Run three server copies and each has its own private pool with its own idea of which keys are burnt out. Restart, and the app forgets everything.

Those six keys are environment variables, set on the server and never shipped to your browser.

GEMINI_API_KEY The first key. If only this one is set, the pool is a pool of one
GEMINI_API_KEY_2 … _5 The extra doors — optional, and each one multiplies daily capacity
STORAGE_ENDPOINT Where finished pictures get uploaded — the address of the file warehouse
STORAGE_ACCESS_KEY The username half of the warehouse credentials
STORAGE_SECRET_KEY The password half. Server-side only, always
STORAGE_BUCKET Which shelf inside the warehouse these images belong on

When a key burns out

Sooner or later a key hits its quota and Gemini refuses. Here is the app catching that and turning it into something a human can read.

CODE 
      // Check if it's a quota/limit error
      if (error.message?.includes('quota') || error.message?.includes('limit') || error.status === 429) {
        geminiApiPool.markKeyAsUnavailable(geminiApiKey, 'Quota exceeded');
        return respErr("Too many users online! VIP users get priority access. You're in queue, please wait a moment or upgrade to VIP for instant access.", 'QUEUE_REQUIRED');
      }
PLAIN ENGLISH

A note explaining the check below.

Three ways to recognise "you are out of budget": the word quota in the error, the word limit, or the code 429. Any one of them counts.

Mark that key burnt out in the pool, so no future request wastes time on it.

Send the user a friendly message instead of a scary error — and a tag, QUEUE_REQUIRED, so the interface knows to show the queue and upgrade prompt.

Close the check. Any other kind of error falls through to the general handler below.

Note what that message really means: "too many users online" is one honest reading, and "we ran out of allowance on all six accounts" is another. Same code, different story.

Bending instead of breaking

Storage is optional. If the warehouse is not set up, the app does not crash — it just carries the picture home in its pockets.

    const hasStorageConfig = process.env.STORAGE_ENDPOINT &&

PLAIN ENGLISH

Before uploading anything, ask: do we actually have a warehouse address?

And a username for it?

And a password?

And a shelf to put things on? All four, or we skip uploading entirely.

🪂
A feature that degrades instead of dying

With no storage configured, the image URL stays as a giant data:image/png;base64,... string and the app still works — the picture just travels inside the response instead of living at a web address. That is a fallback, and it is why a fresh developer can run this app with no cloud account at all.

The documentation trap

This project's own instructions file, CLAUDE.md, says in bold that the generator requires a valid OpenAI API key to function, and lists OPENAI_API_KEY as REQUIRED.

It does not. Nothing in the generator calls OpenAI. Everything you have just read calls Google Gemini.

📄
What the docs say

OPENAI_API_KEY is required. The feature is a "cyberpunk image generator".

⚙️
What the code does

Reads GEMINI_API_KEY through the key pool and calls gemini-2.5-flash-image-preview.

🏷️
Other honest leftovers

The endpoint is still called generate-cyberpunk, and a whole unused video toolkit sits in the codebase with only a demo page importing it.

This is completely normal residue. A product got rebuilt — cyberpunk became Charlie & Lola, OpenAI became Gemini — and the documentation stayed where it was, as documentation always does.

🤖
Why this matters more for you than for a developer

An AI coding assistant reads CLAUDE.md and README files as gospel. Ask one to "fix the image generation" and it may cheerfully add OpenAI code to a Gemini app — and be very confident about it.

So here is the habit worth building. Before you trust a doc, ask what the code actually calls — you can literally say this to your AI assistant:

1
"Search the codebase for which AI provider this feature actually imports."

Searching for a word across every file is called grepping, and it takes seconds.

2
"Show me the file the docs describe, and tell me where they disagree."

Force the mismatch into the open before any code gets written.

3
"Update CLAUDE.md to match reality first, then make the change."

Fixing the doc is a two-minute job that stops the next five confident mistakes.

Think it through

Four situations. None of them have appeared word-for-word above — that is the point.

Every user suddenly sees "Too many users online!" — but your Google dashboard shows plenty of quota left on all six keys. What is the most likely cause?

Users complain the output keeps dropping people's glasses. What is the cheapest place to fix it?

What you can do with this now

✍️
Change the output without changing code

The biggest quality lever in an AI feature is the wording of the brief: make / preserve / forbid.

🚪
Reason about capacity before you build

Rate limits are doors, not fines. Pooling keys buys more doors; it does not make the club bigger.

🔎
Trust the code over the docs

Ask what a feature actually imports before you accept what any README tells you it does.
