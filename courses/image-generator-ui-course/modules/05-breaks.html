Tapping the Walls

Five real faults in this app. Not one of them crashes anything — which is exactly why they are all still here.

Nothing here is on fire

Every one of the five faults on this page is real, is in the app right now, and none of them crash anything. The bugs that crash are the easy ones — they announce themselves.

🔦
The metaphor for this module: a home inspection

An inspector does not wait for the ceiling to come down. They walk the house tapping walls, listening for the hollow spot, checking whether the switch by the door is wired to anything at all. Most of what they find is not dangerous — it is disconnected.

Wires that go nowhere. A light switch left over from a renovation that nobody removed. That is what is in this house — and in yours, and in every shipped product ever looked at under a torch.

📬

1. The reply nobody reads

The server writes message. The browser asks for msg. One word apart, so one whole branch never runs.

🔌

2. Three switches, no wires

Aspect ratio, file format and model tier can never change from the values they were born with.

🎨

3. A style rule waiting by the phone

Hand-written chunky shadows for the buttons that have never once appeared on screen.

🔒

4. A label that tells a fib

The button says you must sign in. Then it generates your picture anyway.

🈳

5. A word that was never delivered

Written in English, translated into Chinese, and never carried the last few metres to the button.

One pattern accounts for all five: two halves that were each written correctly and never introduced to each other.

Fault 1 — the reply nobody reads

When something goes wrong on the server, the app writes back a small note. Every failure note in the whole codebase is built by these fifteen lines.

CODE · src/lib/resp.ts 
export function respErr(message: string, data?: any) {
  return respJson(-1, message, data);
}

export function respJson(code: number, message: string, data?: any) {
  let json: { code: number; message: string; data?: any } = {
    code: code,
    message: message,
  };
  if (data) {
    json.data = data;
  }

  return Response.json(json);
}
PLAIN ENGLISH

Every error in the app leaves through this little door. It takes one thing: a sentence meant for a human.

It passes that sentence on, always stamped with the number -1. Hold on to that -1 — it is the only failure number this app ever sends.

End of the door.

Fault 2 — three switches with the wires cut

The generator carries three settings around with it: a shape for the picture, a file format, and which tier of model to use.

PLAIN ENGLISH

Two things come out of every one of these: the current value, and a state setter — the only hand allowed to change it. Shape starts at 16:9, and setAspectRatio is the only way it will ever move.

Same again for the file format: starts at jpeg, and only setOutputFormat can change it.

And the model tier: starts at pro, movable only by setSelectedModel. The Generate button reads this one to print (10 credits) beside itself.

Search the whole file for those three setter names and you find one mention each — the line that created them. Nothing else ever calls them, so nothing can ever move those values.

Fault 3 — a style rule waiting by the phone

Module 4 showed the trick: every Shadcn brick stamps a small label on itself, and theme.css grabs everything wearing that label and restyles it in one go. [data-slot="card"] does this beautifully. Here is the same trick, one step further.

CODE · src/app/theme.css 
[data-slot="button"][data-variant="default"] {
  background: var(--primary);
  color: var(--primary-foreground);
  border: 2px solid var(--foreground);
  border-radius: var(--radius);
  box-shadow: 4px 4px 0px var(--foreground);
  transition: all 0.2s ease;
}
PLAIN ENGLISH

This first line is the CSS selector: find every element wearing both of these labels. Two attributes, not one — and both are required.

Paint it with the primary colour role, not a hard-coded yellow.

Text in the matching foreground role, so it stays readable if the palette changes.

A fat two-pixel outline in the ink colour — that Charlie-and-Lola storybook edge.

Corners from the shared radius token, so every corner in the app moves together.

And the signature: a hard shadow offset down and right, like a sticker peeled off the page.

Animate any change over a fifth of a second.

End of a rule that has never once been applied to anything.

Fault 4 — the button that asks you to sign in, then does it anyway

Signed out, the Generate button shows a padlock and the words login required. Then you click it, and it generates your picture.

disabled={uploadedImages.length === 0 || isGenerating} The complete list of reasons the button ever refuses: no photo yet, or one is already being drawn. Being signed out is not on it.
🔒
What the label promises

Padlock icon, the words "login required". A clear statement that nothing will happen until you sign in.

▶️
What the button does

Runs generateImage(), which never checks for a session at all. The picture gets made.

🎟️
What the server does

Treats guests deliberately: sends back requiresRegistration: true and charges no credits. The behaviour was designed. Only the wording is out of date.

You have already met the branch that handles this properly — it was line 369 in the spot-the-bug exhibit, the one that offers a full-resolution download in exchange for signing in. That branch works. The label beside it is a leftover from when guests really were turned away.

🏷️
A stale label is a real fault, not a cosmetic one

Some people read "login required", decide they cannot be bothered, and leave — never discovering that the free try was one click away. Nothing in the code is wrong. The product still loses.

Fault 5 — the word that was never delivered

Switch free mode on and the Generate button reads (undefined). The phrase exists. Someone wrote it, someone translated it — it just never travelled the last few metres.

1
The translation files — present ✅

"limited_free": "Limited Free" in English, "限免" in Chinese. Both written, both correct, both sitting there.

2
The Translations interface — missing ❌

The list at the top of imagen-client.tsx declaring every string the component expects. limited_free is not on the list.

3
The mapping in index.tsx — missing ❌

The wrapper from module 2 that hand-copies each string into one object before handing it to the browser. This one never gets copied.

So the button asks for t.buttons.limited_free, is handed nothing at all, and prints the word JavaScript uses for nothing at all: undefined. No error. No warning. Just a strange word on a button.

📮
This is the bill for the hand-written wrapper

Module 2 showed the wrapper copying translations across the client/server wall by hand. The cost: every new piece of text has to be added in three places — the JSON file, the interface, the mapping. Forget one and it fails without a sound.

What the five have in common

💡
Aha: silence is a symptom

A branch that never runs, a rule that matches nothing and a setter that is never called all produce exactly zero errors. Working code and disconnected code look identical from the outside — which is why "it does not crash" is not evidence that it works.

An inspector does not need to know how a house was built to tap the walls. Here is the clipboard — five questions you can ask about your own project this afternoon.

🔌

Is this setter ever called?

"Search the file for every place setAspectRatio is used." If the only hit is where it was created, the control is decorative.

🔤

Do both sides spell it the same?

"List the exact field names the server sends and the ones the client reads." Data crossing a network is never spell-checked by anybody.

🎯

Does this selector match anything?

"Show me an element that has both of these attributes." A style rule for a thing that does not exist is silent, tidy and useless.

🏷️

Does the label match the behaviour?

Read the button out loud, then read what it actually does. Words go stale faster than logic, and nothing checks them.

🔗

Is it wired all the way through?

Anything hand-copied from place to place has as many failure points as it has hops. Count the hops before you add the sixth one.

🤖
For steering AI: the three sentences that end a bug loop

"Why is this broken?" gets you guesses, and the next twenty minutes get you more guesses. Say these three things instead, in this order.

1
Name the station

"This is the client-side handling of the response, in imagen-client.tsx." You learned the seven stations in module 1 for exactly this sentence.

2
Name the mismatch

"The server sends a field called message. The client reads result.msg." A fact, not a symptom. Nothing left to diagnose.

3
Name the fix you want

"Change the client to read result.message. Do not touch resp.ts — everything else in the app depends on it." Otherwise a helpful assistant may fix it from the wrong end and cause a regression in ten other places.

Guesses in, guesses out. Specifics in, patches out.

Five modules ago, this was a box you dropped a photo into

You have not learned to write this app. You were never trying to. Here is what you can actually do now.

🧭
Trace one generation end to end

Seven stations, from the file landing on the page to the finished drawing coming back as a web address. When something breaks, you can name the station.

🎭
Tell the browser half from the server half

And say why the API key can only ever live on one side of that wall — the single most useful line you can draw through any web app.

✍️
Recognise a rented model behind a written brief

The whole Charlie & Lola look is one paragraph of English sent to a general-purpose artist. Change the paragraph, change the product.

🎨
Name a design token instead of a hex code

"Use the secondary token" and "add a variant to buttonVariants" are two sentences that keep an interface from drifting into forty shades of almost-yellow.

🔦
Spot a silent disconnection

Two halves, each written correctly, never introduced. No crash, no error, no clue — until you tap the wall.

📋
The one habit worth keeping

When something looks wrong, name the station before you propose the fix. That single reordering is what separates a five-minute exchange with an AI assistant from a two-hour loop of confident, plausible, wrong suggestions.
