Memory and the Outside World

Every module so far has said "and then it saves it to the database" as if that were one word. It is about six ideas — and the most useful thing about this particular database is that when we went looking for it, it was gone.

Blueprints and Permits

A database is a program whose entire job is to remember things reliably and find them again instantly. This app uses PostgreSQL, rented from a company called Supabase.

There is a file in this project called schema.ts. It is the building's blueprint: this building has a Users room with these dimensions, an Orders room with those, a Credits room down the hall.

The schema: what rooms exist and what shape they are.

The Permits

The Building

The live database, with real people living in it right now. You cannot just hand a builder a new blueprint.

That last card is the whole problem. Redrawing a blueprint is easy. Changing a building people already live in, without knocking it down, is a completely different job — and it is why migrations exist.

And here is one of those rooms as the blueprint actually describes it. The surprise for most people: this is not database language, it is ordinary TypeScript.

CODE 

export const credits = pgTable("credits", {
  id: integer().primaryKey().generatedAlwaysAsIdentity(),
  trans_no: varchar({ length: 255 }).notNull().unique(),
  created_at: timestamp({ withTimezone: true }),
  user_uuid: varchar({ length: 255 }).notNull(),
  trans_type: varchar({ length: 50 }).notNull(),
  credits: integer().notNull(),
  order_no: varchar({ length: 255 }),
  expired_at: timestamp({ withTimezone: true }),
});
PLAIN ENGLISH

Describe a table called credits. Everything in the curly brackets is a column.

A plain counting number that the database fills in itself, and that is the row's primary key: the thing you point at to mean this row and no other.

A reference number, up to 255 characters, that must be present and must never repeat.

When this line was written, stored with its timezone so it means the same instant everywhere in the world.

Whose line it is, and what kind of movement it was. Both required.

The amount — a whole number, positive or negative. This is the plus and minus from last module.

Which order it relates to, if any, and the date it stops counting. Both optional — a signup gift has no order.

🧩
Why Describe the Database in TypeScript?

A tool called Drizzle reads that file and generates the real database instructions. The payoff is that your editor now knows the shape of your data: misspell left_credits and you are told immediately, in red, before the code ever runs. Software that catches your mistakes while you type is worth an enormous amount.

The Permits

There are five permits in this project, in a folder called migrations, with names generated from a word list. They look absurd and they are completely serious.

src/db/migrations/ Every change ever made to the shape of this database, in order
0000_flimsy_toad.sqlThe empty lot becomes a building
0001, 0002Two more changes along the way
0003_steady_toad.sqlAdd a category column to Posts
0004_striped_colossus.sqlAdd a password column to Users

Open 0004_striped_colossus.sql and this is the whole file. One line. Its brevity is the point.

CODE 

ALTER TABLE "users" ADD COLUMN "password_hash" varchar(255);
PLAIN ENGLISH

Change the existing users table — do not rebuild it, do not empty it, just change it.

Add one new column called password_hash, holding up to 255 characters.

That is the entire permit. This is written in SQL, the language databases actually speak — and you can read it, which is exactly the point.

Module 3's email-and-password sign-in door needed somewhere to store a scrambled password. This file is the moment that door became possible.

💡
Ask For the Migration, Not Just the Change

When you tell an AI assistant "add a phone number field to users", it may edit the blueprint and quietly push the change straight into your database. Say instead: "change the schema and generate a migration for it." The difference is a file you can read, review, keep in version history, and run identically on your laptop, on the test site and in production. Invisible schema changes are how two copies of the same app drift apart.

The Day the Database Vanished

While making this course, we tried to connect to this app's database. It answered:

💀
tenant or user not found

The Supabase project had been deleted — most likely reclaimed as an idle free-tier project. Nothing in the code is wrong. The code is fine. The thing the code depends on stopped existing.

Learn the shape of that error, because you will meet it again. It appeared at the connection stage — before a single one of the app's queries ever ran. That timing is the tell.

1
Errors at the connection stage

"Not found", "authentication failed", "could not connect" — before any of your queries run. Almost never your code. Suspect the address, the credentials, or the service itself.

2
Errors from a specific query

"column does not exist", "duplicate key". The connection is fine — this is your code, or a migration that was never run.

3
No error, wrong answer

Everything "works" but the numbers are wrong. The hardest kind. Module 7 is about these.

Two things would have caught this earlier: a health check that actually touches the database rather than just returning "OK", and knowing in advance that free tiers reclaim idle projects.

When the database does exist, the app does not open a new connection for every question it asks. Opening one is slow, so it keeps a small set open and reuses them — a connection pool.

max: 10 At most ten open lines at once. The eleventh request waits its turn rather than overwhelming the database.
idle_timeout: 30 A line sitting unused for 30 seconds gets hung up. Do not pay to hold lines nobody is talking on.
connect_timeout: 10 If dialling takes more than 10 seconds, give up and fail loudly instead of hanging forever.

The Password in the Code

There is a patch in src/db/index.ts, written to work around a database password containing a / character that broke the connection address. We have replaced the password with [REDACTED] below. The real file has it in plain text.

Two things are wrong here. Click the line that worries you most:

2 if (databaseUrl.includes(':[REDACTED]@')) {
3   databaseUrl = databaseUrl.replace(':[REDACTED]@', ':[REDACTED-ENCODED]@');
4   console.log('Applied URL encoding for database password special character');

Nobody should feel bad about this. It is a 2am "just make it work" patch, and it did work. It is also exactly what an AI assistant will write if you say "the database URL is failing" and paste the error — a fix aimed at your one symptom rather than at the cause.

🔐
Secrets Never Go in Code

Passwords, API keys and webhook secrets belong in environment variables, set on the server and never committed. And when a fix works only for one exact value, ask what the general version of that fix would be. "Handle any password with special characters" is a different instruction from "handle this password" — and you are the one who has to ask for it.

Three Things You Do Not Control

The database is rented. So is the AI, the image storage, and the payments. Each one fails in its own particular way.

✨

Google Gemini

Makes the cartoon. Fails with quota exceeded, which arrives as HTTP 429.

🪣

Cloudflare R2

Object storage for finished images. Fails by being unreachable, or by never having been configured at all.

💳

Stripe

Takes the money. Fails by rejecting a signature, or by having its webhook pointed at the wrong address.

💡
Your App Is Mostly a Coordinator

Strip out the rented parts and there is surprisingly little left: some rules about credits, some pages, and a lot of careful arranging. That is normal and it is not a criticism — but it changes what "the app is broken" usually means. More often than not it means an outside service said no, and that is where to look first.

A Bank of Phone Lines

Each Gemini API key has a daily limit. So the app does not have one key — it reads up to six from environment variables and rotates through them like a switchboard rotating through phone lines.

GEMINI_API_KEY Line one. The only one that must exist.
GEMINI_API_KEY_1 … _5 Five more optional lines. Any that are not set are quietly filtered out of the list at startup — no error, the pool just ends up smaller.

Something went wrong with the AI call. Work out whether it was a rate limit by checking three different ways, because different services phrase it differently.

"Too many users online, VIP users get priority access." A technical limit has been reframed as evidence the product is popular, and as a reason to pay. That is a deliberate product decision, living inside error-handling code.

Worse, But Working

What if the image storage is not configured at all? The app does not error. It quietly does something worse instead.

CODE 

    let finalImageUrl = `data:${generatedImageMimeType};base64,${generatedImageData}`;
    let storedFilename = filename;
 
    // Store image if storage is configured
    const hasStorageConfig = process.env.STORAGE_ENDPOINT &&
                            process.env.STORAGE_ACCESS_KEY &&
                            process.env.STORAGE_SECRET_KEY &&
                            process.env.STORAGE_BUCKET;
PLAIN ENGLISH

Start by assuming the worst case: the image address is the entire image, encoded as a gigantic block of text called a data URL.

Note that this is the default, set before anything is even attempted. The good outcome is the upgrade; the poor outcome is the starting point.

Now check whether proper storage is set up — all four settings must be present. Miss one and storage counts as unconfigured.

If they are all there, upload the image and replace that giant text block with a short, real web address.

🪂
Graceful Degradation

Name the pattern: graceful degradation. The user still gets their cartoon. But the reply is now megabytes instead of bytes, the image is saved nowhere, and there is no link they can share. Worse, but working — and worth knowing that this is what "it feels slow today" sometimes actually is.
